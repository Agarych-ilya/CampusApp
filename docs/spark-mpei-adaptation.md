## Что добавлено

### БАРС — калькулятор и прогноз оценок

Источник идеи: `ui/bars/GradeForecastHelper.kt`,
`ui/bars/SubjectCard.kt`.
Реализация CampusApp:
- `lib/features/profile/data/subject_grade_forecast.dart`;
- `lib/features/profile/view/subject_forecast_sheet.dart`;
- кнопка в раскрытом предмете на `profile_screen.dart`.

Для оценённых КМ показывается взвешенное среднее:

`Σ(grade * weight) / Σ(weight оценённых работ)`.

Отдельно показывается уже набранный балл от **всех**
известных весов, включая открытые мероприятия:

`Σ(grade * weight) / Σ(weight всех работ)`.

Текущий прогноз строится с порогами 4.2, 3.5, 2.5 из Spark.
Порог 4.2 в исходнике назван ориентиром автомата;
порог НЕ заменяет правила конкретной дисциплины и оценку БАРС.
Для открытых КМ вычисляется минимальная средняя будущая оценка
для достижения выбранного порога и проверяется, достижим ли он.

Пересдача ранее выставленной двойки: эффективная оценка
`(2 + новая оценка) / 2`. Если БАРС уже прислал строку `2/5`,
пересдача учитывается один раз, без удвоения коэффициента.
Оценки, выбранные в симуляторе, остаются только в оперативной памяти,
не записываются ни в БАРС, ни в бэкенд, ни в сохранённый список оценок.

КМ без корректного веса исключаются из расчёта; приложение показывает
их число. Неоценённые КМ не становятся «нулевыми» в фактическом среднем.

### Расписание — прогресс текущей пары

Источник идеи: `ui/schedule/LessonBreakProgress.kt`.
Реализация CampusApp:
- `lib/features/schedule/data/lesson_break_progress.dart`;
- `lib/features/schedule/widgets/lesson_live_progress.dart`;
- интеграция в `LessonCard` без изменения цветовой схемы и бронирования.

95 минут занятия → 45 минут + 5-минутный перерыв + 45 минут.
Отображается только на текущей паре, обновление каждые 30 секунд.
Временная зона для расчёта — Москва (UTC+3), независимо от телефона.
Другие интервалы делятся на две половины вокруг 5-минутной паузы;
короткие занятия (менее 15 минут) без разделения.

## Что уже существовало в CampusApp

- журнал и проверка прав старосты через БАРС;
- загрузка студентов группы и отметка «Н»;
- личные и групповые заметки к парам;
- плавающая нижняя навигация;
- статистика/рейтинг БАРС.

Эти компоненты не заменялись реализациями Spark на Kotlin:
они интегрированы в текущий Flutter/NestJS и имеют собственные
механизмы сохранения и защиты прав.

## Не перенесено

- запись в официальный журнал БАРС через HTML-формы Spark:
  CampusApp ведёт собственный серверный журнал, поэтому такой перенос
  может привести к несогласованным данным без отдельной проверки;
- системные уведомления о заметках после закрытия приложения:
  для этого потребуется полноценная платформенная интеграция
  уведомлений и разрешений Android/iOS;
- модуль почты ОСЭП Spark и его учётные данные;
- вспомогательный отчёт старосты Spark.

Тесты расчётов:
`test/features/profile/subject_grade_forecast_test.dart`;
`test/features/schedule/lesson_break_progress_test.dart`.


## Реализация остальных идей по SPARK_ideas_for_CampusApp.md

Этот раздел отражает работу в ветках \`map\` **обоих** репозиториев.
Код добавлен, но запуск приложения и реальный БАРС/РУЗ из этого
окружения не проверены. Тесты CI настроены, но успешный прогон
пока не подтверждён.

### 1. Автоопределение старосты и несколько групп — добавлено

Сервер: \`BarsSessionVerifier.discoverGroupCandidates()\`,
\`AttendanceController\` с маршрутами
\`GET /services/attendance/managed-groups\`,
\`POST /services/attendance/managed-groups/discover\`,
\`POST /services/attendance/managed-groups/verify\`.

Кандидаты читаются из авторизованного меню и списка БАРС
только для текущей сессии; **ссылка на группу не даёт прав**.
Каждая группа подтверждается отдельно через \`verifyStarosta\`.
Результаты привязаны к эпохе текущей BARS-сессии и сбрасываются
при её смене/переподтверждении.

Flutter: \`StarostaCabinetScreen\` в разделе «Сервисы».
Карточка видима только после подтверждённой роли. Пять нижних
иконок не меняются (ранее пользователь просил сохранить их пять).
Из кабинета можно выбрать несколько подтверждённых групп.
При смене группы прежний список и отчёт очищаются.

### 2. Полный список студентов — добавлен серверный проход по страницам

Сервер: \`BarsRosterFetcher.fetch()\` читает только защищённые страницы,
проверяет ФИО, активный статус, ID/почту; при наличии постраничности
пытается пройти страницы, сверяя счётчик и идентичность строк. Отказывается
сохранять неполный, конфликтующий или повторяющийся список.
Дополнительные группы доступны только после отдельной проверки прав.

Требуется проверка на действующей группе БАРС, в том числе с
Ajax/DataTables-пагинацией: HTML может отличаться от статической фикстуры.

### 3. Сохранение посещаемости — уже было частично, официальный БАРС не изменяется

\`AttendanceService.saveAbsences()\` сверяет участников группы,
обновляет отметки атомарно и ведёт историю.
\`correctClosedAttendance()\` позволяет снять «Н» с проверкой
предыдущего статуса, против потери параллельных изменений.
Flutter: \`AttendanceLessonScreen\`.

**Официальный POST в БАРС НЕ добавлен**. Требуется отдельное
исследование фактической формы \`SG/Lesson/EditLesson\`,
\`__RequestVerificationToken\`, сериализованного JSON,
идентификатора причины пропуска, повторного чтения формы,
конфликтов и подтверждения ответа. Не использовать предустановленный
числовой ID причины пропуска.

### 4. Отчёты — добавлен отчёт CampusApp, не официальный XLS БАРС

Сервер: \`GET /services/attendance/reports\` с обязательной проверкой
доступа старосты к выбранной группе, периодом до 93 дней,
только закрытыми занятиями и исходными roster snapshot-строками.

Flutter: \`StarostaCabinetScreen\` — фильтры по студенту/предмету
применяются локально к загруженному отчёту. Отчёт пересчитывается
только по нажатию. Экспорт UTF-8 CSV с BOM и защитой от Excel
formula injection в файл приложения; ID студента не экспортируется.
Файл хранится на устройстве **только после явного экспорта**.
XLS/XLSX/HTML из официального БАРС пока не импортируются.

### 5. Расчёт оценок — добавлено ранее

См. раздел «БАРС — калькулятор и прогноз оценок» выше.
Парсер пересдачи используется и при публикации среднего в рейтинге
через \`GradeScoreSnapshot\`; не удваивает пересдачу вида \`2/5\`.

### 6. Преподаватели и аудитории — read-only поиск добавлен

Сервер: \`GET /schedule/ruz/search\`,
\`GET /schedule/ruz/lessons\` через фиксированные пути
\`ts.mpei.ru\`. Только типы \`person\` и \`auditorium\`,
валидация ID, дат, объёма ответа, без произвольного URL клиента.
Flutter: кнопка поиска в шапке расписания → \`RuzLookupScreen\`.
Данные только для просмотра и не используются для бронирования.
**Фактический ответ API МЭИ в этой среде не подтверждён**;
на реальном соединении может потребоваться адаптация полей.

### 7. Прогресс пары — добавлено; системные напоминания ещё нет

\`LessonBreakProgress\` и \`LessonLiveProgress\` переносят логику
45+5+45 минут, часовой пояс Москвы, обновление каждые 30 с.
Локальные уведомления AlarmManager/Android, разрешения iOS
и восстановление после перезагрузки ещё не реализованы.

### 8. Навигация и дни — существующая реализация сохранена

\`CampusGlassDock\` имеет анимацию активной вкладки.
Расписание поддерживает перелистывание недель/дней.
Вместо 6-й нижней иконки кабинет старосты представлен
условной карточкой сервиса, чтобы сохранить пользовательский дизайн
с пятью иконками.

### 9. Защита — частично, необходим внешний security review

Для BARS-куки действуют HTTPS или loopback ADB, ограничение origin,
доверенные маршруты, серверная сверка владельца и CSRF.
Отчёты и списки не выдаются по одному лишь \`group\`.
Роль привязана к текущему серверному логину.
Полная ревизия защиты хранения BARS-сессий, логирования,
сроков кэша и инцидентов **не проводилась**.

Сервер: \`starosta-cabinet.spec.ts\`,
\`bars-managed-groups.spec.ts\`, \`ruz-entity.service.spec.ts\`
и имеющиеся тесты \`bars-roster-fetcher.service.spec.ts\`.

Flutter: \`starosta_report_csv_test.dart\`,
\`ruz_entity_api_test.dart\` плюс тесты средних оценок и
прогресса пары.

CI GitHub Actions: \`.github/workflows/campus-map-ci.yml\` для

не считать перенос полностью готовым.
